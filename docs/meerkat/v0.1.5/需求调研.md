# 需求调研

## 现有文件存储架构

### 1. 文件 artifact 接口

`src/files/file-artifact-store.ts` 定义了 `FileArtifactStore` 接口，包含：

- `put`: 写入文件元数据与字节。
- `get`: 按 id 读取元数据。
- `open`: 按 id 读取字节流。
- `listOwnedByScopes`: 按 scope 列出文件（支持 cursor 分页、createdInScope 过滤、includeDisabled）。
- `resolveByOwnerPaths`: 按 owner + path 解析。
- `setEnabled` / `delete`: 启停与删除。

接口实现目前有：

- `createMemoryFileArtifactStore`：Map 内存实现，用于无 `DATABASE_URL` 时。
- `createPostgresFileArtifactStore`：Postgres 实现，schema 见同文件。

### 2. 字节存储

`src/files/durable-byte-store.ts` 提供：

- `createMemoryDurableByteStore`
- `createLocalDurableByteStore(dir)`：把字节存在 `<dir>/files/<sha256>`，按 sha256 去重。
- `createS3DurableByteStore`

桌面版当前 `snapshotStore` 未显式配置，因此 `wiring.ts:578-584` 默认使用 `createLocalDurableByteStore(join(config.dataDir, "docstore"))`。也就是说，**文件字节本身已经落在本地磁盘**，丢失的只是元数据注册表。

### 3. 配置与路由

`src/config.ts`：

- 已有 `sessionStore: "memory" | "postgres" | "sqlite"`。
- 已有 `sqlitePath?: string`，当 `SESSION_STORE=sqlite` 时解析为 `SQLITE_PATH ?? join(dataDir, "meerkat.db")`。
- `src/config.ts:665-670` **当前明确禁止** `ARTIFACT_STORE=sqlite`：
  ```ts
  for (const key of ["RUN_STORE", "ARTIFACT_STORE"] as const) {
    if (env[key] === "sqlite") {
      throw new Error(`${key}=sqlite is not supported ...`);
    }
  }
  ```

`src/wiring.ts:585-587`：

```ts
const files: FileArtifactStore = config.databaseUrl
  ? createPostgresFileArtifactStore(config.databaseUrl, fileBytes)
  : createMemoryFileArtifactStore(fileBytes);
```

桌面版 `proc.rs` 启动 core 时：

- 设置了 `SESSION_STORE=sqlite`。
- 没有设置 `DATABASE_URL`。
- 没有设置 `ARTIFACT_STORE`。

因此 `fileArtifactStore` 必然回退到内存实现，重启后元数据丢失。

### 4. SQLite 基础设施

`src/persistence/sqlite-map.ts` 提供了：

- `openSqliteDatabase(sqlitePath)`：封装 `node:sqlite/DatabaseSync`。
- `createSqliteMapFactory(sqlitePath)`：创建 `DurableMap` 工厂，自动启用 WAL。

`src/sessions/sqlite-session-store.ts` 是一个完整示例：

- 使用 `openSqliteDatabase` 打开 db。
- 启用 `PRAGMA journal_mode = WAL`。
- 在构造函数中执行 schema 初始化（`CREATE TABLE IF NOT EXISTS`）。
- 使用 `db.prepare` 预编译语句并复用。
- 提供 `close()` 关闭数据库。

### 5. 现有测试

- `test/file-artifact-store.test.ts`：测试内存 store 和 durable byte store 的核心行为。
- `test/postgres-file-artifact-store.test.ts`：在 `DATABASE_URL` 存在时测试 Postgres store，覆盖 put/list/setEnabled 等。

可以借鉴 `postgres-file-artifact-store.test.ts` 的结构，为 SQLite store 写一份 `test/sqlite-file-artifact-store.test.ts`。

## 方案对比

| 方案 | 优点 | 缺点 | 是否触及内核 |
|---|---|---|---|
| A. 新增 SQLite file artifact store，由 `ARTIFACT_STORE=sqlite` 启用 | 与现有 SESSION_STORE=sqlite 共用同一数据库；离线可用；单文件迁移简单 | 需要新增 `src/files/sqlite-file-artifact-store.ts`，并修改 `config.ts` 和 `wiring.ts` | 是（触及 core 配置和 wiring） |
| B. 桌面版单独启动一个 Postgres | 无需改 core | 桌面版需带 Postgres，离线/安装体验差 | 否 |
| C. 用 `createSqliteMap` 把元数据当 JSON 存 | 实现极快 | 无法利用 SQL 索引和分页，listOwnedByScopes 性能差 | 是 |
| D. 把元数据写进本地 JSON 文件 | 简单 | 无事务、无索引、易损坏 | 否（Meerkat 层） |

## 推荐方案

**方案 A**：新增 `src/files/sqlite-file-artifact-store.ts`，schema 复用 Postgres 版并做 SQLite 适配（如 BOOLEAN 用 INTEGER、数组查询用 `IN` 子句）。

启用方式：
- `src/config.ts` 允许 `ARTIFACT_STORE=sqlite`，并从 `SQLITE_PATH` 或 `dataDir/meerkat.db` 解析路径。
- `src/wiring.ts` 在 `config.artifactStore === "sqlite" && config.sqlitePath` 时使用 SQLite 实现。
- `deploy/layers/meerkat/desktop/src-tauri/src/proc.rs` 启动 core 时设置 `ARTIFACT_STORE=sqlite`，复用 `SQLITE_PATH` 指向与 session store 同一个 db 文件。

这样文件元数据和会话数据落在同一个 SQLite 文件里，符合桌面版单用户、离线、轻量的定位。

## 风险与注意事项

1. **触及内核**：`config.ts` 和 `wiring.ts` 属于 core，需要写 ADR。
2. **与 Postgres 的兼容性**：当 `DATABASE_URL` 存在时仍优先用 Postgres；SQLite 仅作为无 DATABASE_URL 时的桌面版选项。
3. **Schema 迁移**：首次实现时 `CREATE TABLE IF NOT EXISTS` 即可；后续如加字段需写迁移。
4. **并发**：SQLite WAL 模式可支持一定程度的读写并发，但不如 Postgres。桌面版单用户场景足够。
5. **已有数据**：当前内存数据无法迁移，升级后历史文件仍会丢失，需在 ADR 里说明。
