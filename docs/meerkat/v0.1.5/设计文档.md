# 设计文档

## 背景与目标

桌面版 Meerkat 使用 `SESSION_STORE=sqlite`，但 `fileArtifactStore` 因缺少 `DATABASE_URL` 回退到内存实现，导致文件元数据在 core 重启后丢失（issue #34）。

本设计目标：在桌面版启用 SQLite 持久化的文件 artifact 元数据存储，同时保持现有 Postgres 部署的兼容性。

## 方案概述

新增 `src/files/sqlite-file-artifact-store.ts`，schema 与 Postgres 版 `file_artifacts` 表对齐。通过环境变量 `ARTIFACT_STORE=sqlite` 启用，元数据写入与 session store 同一个 SQLite 文件（`%APPDATA%\com.meerkat.desktop\meerkat.db`）。

文件字节继续走现有 `DurableByteStore`（桌面版为本地 `docstore/files/<sha256>`），不改动。

## 详细设计

### 1. SQLite schema

与 `postgres-file-artifact-store.ts` 对齐，SQLite 适配点：

- `BIGINT` → `INTEGER`
- `BOOLEAN` → `INTEGER`（`0`/`1`）
- 默认值 `TRUE` → `1`
- 部分索引 `WHERE enabled = TRUE` → `WHERE enabled = 1`

```sql
CREATE TABLE IF NOT EXISTS file_artifacts(
  id               TEXT PRIMARY KEY,
  kind             TEXT NOT NULL DEFAULT 'file',
  owner_scope_id   TEXT NOT NULL,
  path             TEXT NOT NULL,
  name             TEXT NOT NULL,
  mimetype         TEXT NOT NULL,
  size_bytes       INTEGER NOT NULL,
  blob_key         TEXT,
  sha256           TEXT,
  direction        TEXT NOT NULL,
  created_by       TEXT NOT NULL,
  created_in_scope TEXT,
  created_at       INTEGER NOT NULL,
  updated_at       INTEGER NOT NULL,
  enabled          INTEGER NOT NULL DEFAULT 1,
  source           TEXT NOT NULL DEFAULT 'live'
);

CREATE INDEX IF NOT EXISTS file_artifacts_owner_created
  ON file_artifacts (owner_scope_id, created_at DESC, id DESC);
CREATE INDEX IF NOT EXISTS file_artifacts_owner_path
  ON file_artifacts (owner_scope_id, path);
CREATE INDEX IF NOT EXISTS file_artifacts_scope_created
  ON file_artifacts (created_in_scope, created_at DESC, id DESC) WHERE enabled = 1;
```

### 2. `src/files/sqlite-file-artifact-store.ts`

参照 `postgres-file-artifact-store.ts` 实现 `FileArtifactStore` 接口：

- 构造函数接收 `sqlitePath: string` 和 `byteStore: DurableByteStore`。
- 使用 `openSqliteDatabase(sqlitePath)` 打开 db。
- 启用 WAL：`PRAGMA journal_mode = WAL`。
- 构造函数中执行 schema 初始化（`CREATE TABLE IF NOT EXISTS` + indexes）。
- 预编译语句复用（`db.prepare`）。
- `BOOLEAN` 字段在写入时转 `1/0`，读取时转 `true/false`。
- `put` 行为与 Postgres 一致：按 `id` 先查，存在则返回现有行（`created: false`），不存在则写入。
- `listOwnedByScopes` 按 `(created_at DESC, id DESC)` 排序，支持 `cursor`、`createdInScope`、`includeDisabled`。
- `resolveByOwnerPaths` 使用 `(owner_scope_id = ? AND path = ?)` 条件拼接实现：按 `refs` 数量生成 OR 条件组，参数平铺为 `[owner1, path1, owner2, path2, ...]`，SQLite 不支持 `unnest` 与多列 row-valued `IN`，该方案无需临时表且与现有调用规模匹配。
- `put` 使用 `INSERT ... ON CONFLICT (id) DO NOTHING` 保证并发幂等；构造 `INSERT` 时显式写入 `source = 'live'`，不依赖默认值。
- 提供 `close()` 关闭 db（返回类型与 `createSqliteSessionStore` 一致，即 `FileArtifactStore & { close(): void }`）。

### 3. `src/config.ts` 改动

新增 `artifactStore: "memory" | "postgres" | "sqlite"` 字段到 `Config` 接口。

解析逻辑：

```ts
let artifactStore: Config["artifactStore"] = "memory";
if (env.ARTIFACT_STORE === "postgres") artifactStore = "postgres";
else if (env.ARTIFACT_STORE === "sqlite") artifactStore = "sqlite";
else if (env.ARTIFACT_STORE) {
  throw new Error("ARTIFACT_STORE must be one of memory, postgres, sqlite");
}
```

放宽 `sqlitePath` 解析条件：

```ts
const needsSqlite = env.SESSION_STORE === "sqlite" || env.ARTIFACT_STORE === "sqlite";
const sqlitePath = needsSqlite
  ? resolve(env.SQLITE_PATH ?? join(dataDir, "meerkat.db"))
  : undefined;
```

互斥检查更新为：

```ts
if ((env.SESSION_STORE === "sqlite" || env.ARTIFACT_STORE === "sqlite") && env.DATABASE_URL) {
  throw new Error(
    "SESSION_STORE=sqlite or ARTIFACT_STORE=sqlite cannot be combined with DATABASE_URL — ...",
  );
}
```

移除当前 `src/config.ts:665-670` 对 `ARTIFACT_STORE=sqlite` 的禁止抛错；非法 `ARTIFACT_STORE` 值显式报错。

在返回的 config 对象中加入 `artifactStore` 和 `sqlitePath`。

### 4. `src/wiring.ts` 改动

`files` 路由更新为：

```ts
const files: FileArtifactStore = config.databaseUrl
  ? createPostgresFileArtifactStore(config.databaseUrl, fileBytes)
  : config.artifactStore === "sqlite" && config.sqlitePath
    ? createSqliteFileArtifactStore(config.sqlitePath, fileBytes)
    : createMemoryFileArtifactStore(fileBytes);
```

优先级：

1. `DATABASE_URL` 存在 → Postgres（兼容现有 SaaS 部署）。
2. `ARTIFACT_STORE=sqlite` 且 `sqlitePath` 有效 → SQLite（桌面版）。
3. 否则 → memory（默认兜底）。

### 5. `deploy/layers/meerkat/desktop/src-tauri/src/proc.rs` 改动

core 启动命令增加环境变量：

```rust
.env("ARTIFACT_STORE", "sqlite")
```

`SQLITE_PATH` 不传，复用 `DATA_DIR` 推导默认值：

```
%APPDATA%\com.meerkat.desktop\meerkat.db
```

## 错误处理

当 `ARTIFACT_STORE=sqlite` 时，若 `sqlitePath` 无法打开（目录不存在、不可写、文件损坏等），core 启动直接报错，**不回退到 memory**。这是快速失败原则，避免用户误以为持久化已生效。

`openSqliteDatabase` 已封装该错误并抛出带有路径信息的异常，启动流程会自然失败。

## 测试策略

1. **单元测试**：新增 `test/sqlite-file-artifact-store.test.ts`，覆盖：
   - put 幂等（按 id 去重，不重复写 bytes）。
   - get / open 正反面。
   - listOwnedByScopes 排序、分页、scope 过滤、createdInScope、includeDisabled。
   - setEnabled / delete。
   - 跨 store 实例读取（持久化验证）。

2. **集成测试**：
   - `test/files-http.test.ts` 等现有测试应继续通过（使用 memory store 时）。
   - 手动验证：桌面版生成文件 → 重启 → 「文件」面板仍能看到。

3. **不破坏现有测试**：Postgres 测试依赖 `DATABASE_URL`，SQLite 测试使用临时文件，互不干扰。

## 迁移与兼容性

- **已有内存数据**：无法迁移，升级后历史文件元数据丢失。聊天附件芯片可能仍显示，但点击下载会失败。在 ADR 中记录该限制。
- **SaaS 部署**：`DATABASE_URL` 优先，行为不变。
- **开发者本地**：未设置 `ARTIFACT_STORE` 时仍为 memory，行为不变。
- **桌面版**：新增 `ARTIFACT_STORE=sqlite` 后首次启动自动建表，无感升级。
