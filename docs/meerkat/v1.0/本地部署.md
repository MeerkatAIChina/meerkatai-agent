# 本地部署文档 —— 在你自己的电脑上跑通 Meerkat

本文档记录 v1.0 二开成果（数据分级模型路由 + TRIZ Skills 包）在 **Windows 本机**的完整部署过程，含所有已踩过的坑。照做可在约 30 分钟内从零跑通。

> 运行形态：浏览器 → web-ui(:8096) → qm core(:8081) → classifier sidecar(:8090)；core 通过 custom provider 调 Kimi Code 模型，沙盒工具跑在本机 Docker 容器里。

## 0. 前置条件

| 依赖 | 要求 | 说明 |
|------|------|------|
| Node.js | ≥ 24 | 直接跑 TS（`node src/index.ts`） |
| Docker Desktop | 已安装且**daemon 在运行** | 沙盒工具必需；不启动也能聊天，但工具执行不可用 |
| Kimi Code key | `sk-kimi-...` | **必须是 Kimi Code（会员订阅）key**，不是开放平台 key；两者不通用 |
| Git Bash | 任意 | 启动脚本以 bash 编写 |
| 代理（可选） | 127.0.0.1:7890 | npm install / 拉镜像时可能需要 |

仓库分支：`feature/meerkat`（main 留给上游同步，不要合并）。

## 1. 一次性准备

```bash
# 仓库根目录 E:\projects\meerkatai-agent
npm install
(cd deploy/layers/meerkat/classifier && npm install)
(cd plugins/web-ui && npm install && npm run build)   # 网络受限时加 --proxy http://127.0.0.1:7890 --https-proxy http://127.0.0.1:7890
```

写 `.env`（仓库根，已被 .gitignore 覆盖）：

```dotenv
ORG_ID=meerkat
PORT=8081
HARNESS=pi
ALLOW_UNAUTHENTICATED_CORE=1
CLASSIFIER_URL=http://localhost:8090/classify
CONNECTOR_SECRET_KEY=<随机字符串，固定后不要换>
PI_MODEL=kimi-k2.6
```

注意：`CLASSIFIER_URL` 必须带 `/classify` 路径（ADR-009）。

## 2. 一键启动

```bash
export MEERKAT_KIMI_KEY=sk-kimi-你的key
bash scripts/meerkat-local-up.sh
```

脚本依次完成：

1. 注册 buildx 插件（Docker Desktop 自带的 `docker-buildx.exe` 拷到 `~/.docker/cli-plugins/`，**不做这步 `docker build` 是 legacy builder，`TARGETARCH` 为空导致 fly/Dockerfile 第 9 步必炸**）；
2. 若缺沙盒镜像则用 buildx 构建 `qm-sandbox-base:dev` + `qm-sandbox-local:latest`（首次约 10-20 分钟）；
3. 起 sidecar(:8090)、core(:8081)、web-ui(:8096)；
4. 通过 admin API 注册 custom provider（Kimi Code）、注册并导入 TRIZ skill pack、把组织级 base model 设为 `kimi-k2.6`。

然后打开 **http://localhost:8096**，任意 id 登录即可使用。

> **为什么 core 重启后必须重跑脚本**：本地部署用内存存储（未接 Postgres），provider 注册、skill pack 导入、组织 base model 都是易失的。脚本是幂等的，重跑即恢复。

## 3. 验证清单

| 验证 | 方法 | 期望 |
|------|------|------|
| sidecar 分类 | `curl localhost:8090/health` | `{"status":"ok"}` |
| TRIZ 路由 | 发一条 TRIZ 消息 | 模型回复，且工具调用读取了 `skills/triz-*/SKILL.md` |
| PII 路由 | 发一条含身份证号的消息 | sidecar 判 L1，走 local-secure 策略 + session pin |
| 沙盒工具 | 让模型执行 `uname -a` | 返回容器内 Linux 输出 |

## 4. 踩坑记录（别人大概率会再踩）

1. **Kimi key 类型**。`sk-kimi-` 前缀是 Kimi Code 订阅 key，端点是 `https://api.kimi.com/coding/v1`（OpenAI 兼容）；拿去打 `api.moonshot.cn` / `api.moonshot.ai` 只会得到 401。
2. **Docker Desktop 必须从完整用户环境启动**。从精简环境（缺 `ProgramData` 变量）拉起会崩溃循环报 `unable to get 'ProgramData'`，并把 `~/AppData/Local/Docker/backend.error.json` 写到 1 GB+。正确姿势：开始菜单启动，或 `ProgramData='C:\ProgramData' nohup "Docker Desktop.exe" &`。
3. **core 进程 PATH 里必须有 docker CLI**。否则沙盒报 `requires a running Docker daemon` 即使 daemon 在跑。启动脚本已把 `C:\Program Files\Docker\Docker\resources\bin` 加进 PATH。
4. **legacy builder 没有 TARGETARCH**。`npm run sandbox:local:build` 默认走 legacy builder，fly/Dockerfile 里 `case "$TARGETARCH"` 落到 `*) exit 1`。必须先注册 buildx 插件并用 `docker buildx build --load`（脚本已内置）。
5. **组织默认模型在 boot 时冻结**。`baseModelDefault` 在 custom provider 注册表水合前解析，`PI_MODEL=kimi-k2.6` 不生效，新用户会落到 `claude-opus-5` 被 403（"provider isn't configured"）。解法：boot 后用 admin API 设组织级 base model：`PUT /v1/admin/scopes/org:meerkat/base-model`，body `{"modelId":"kimi-k2.6"}`（脚本已内置）。
5b. **Web UI 模型下拉列表也要设**。不设 `webui-models` 时，前端模型下拉默认列出内置模型（Fable 5 / Opus 5…），用户选中未配置的模型同样 403。解法：`PUT /v1/admin/scopes/org:meerkat/webui-models`，body `{"ids":["kimi-k2.6"]}`，下拉只剩可用模型且默认选中它（脚本已内置）。
6. **org 作用域的 runtime-config 不开放**。`PUT /v1/runtime-config` 只允许 personal 作用域；组织级要走 `/v1/admin/scopes/:scope/:resource`。
7. **admin 调用身份头**。`x-admin-actor: admin-alice@meerkat`（内存模式默认种子管理员；`@` 后缀必须等于 `ORG_ID`）。
8. **npm 不在 PATH / 网络受限**。用 `cmd //c "npm.cmd install --proxy http://127.0.0.1:7890 --https-proxy http://127.0.0.1:7890"`。

## 5. 进程管理

三个进程都以后台方式运行，日志在 `/tmp/meerkat-{sidecar,core,webui}.log`。停止：

```bash
for p in 8090 8081 8096; do
  PID=$(netstat -ano | grep ":$p" | grep LISTENING | awk '{print $5}' | head -1)
  [ -n "$PID" ] && taskkill //F //PID $PID
done
```

## 6. 已知限制

- **内存存储**：会话、注册信息、审计均不落盘，core 重启即清空（重跑脚本恢复注册，会话不可恢复）。生产部署需接 Postgres（设 `DATABASE_URL` 等，core 侧已支持）。
- **两个路由策略共用同一模型**：微调模型 meerkat-triz-v1 未上线，`local-secure` 与 `meerkat-triz-v1` 暂时都指向 `kimi-k2.6`（`deploy/layers/meerkat/classifier/local-routes.json`）。模型上线后改这一个文件即可。
- `ALLOW_UNAUTHENTICATED_CORE=1` 仅限隔离的本机开发，任何可被他人访问的部署都不能开。
