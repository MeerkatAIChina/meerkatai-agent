# 本地部署文档 —— 在你自己的电脑上跑通 Meerkat

本文档记录 v1.0 二开成果（数据分级模型路由 + TRIZ Skills 包）在 **Windows 本机**的完整部署过程。照做可在约 30 分钟内从零跑通；遇到问题先翻最后的 FAQ，都是我们实测踩过的坑。

> 运行形态：浏览器 → web-ui(:8096) → qm core(:8081) → classifier sidecar(:8090)；core 通过 custom provider 调 Kimi Code 模型，沙盒工具跑在本机 Docker 容器里。

## 0. 前置条件

| 依赖 | 要求 | 说明 |
|------|------|------|
| Node.js | ≥ 24 | 直接跑 TS（`node src/index.ts`） |
| Docker Desktop | 已安装且**daemon 在运行** | 沙盒工具必需；不启动也能聊天，但工具执行不可用 |
| Kimi Code key | `sk-kimi-...` | **必须是 Kimi Code（会员订阅）key**，不是开放平台 key；两者不通用 |
| Git Bash | 任意 | 启动脚本以 bash 编写 |
| 代理（可选） | 127.0.0.1:7890 | npm install / 拉镜像时可能需要 |

仓库分支：`feature/meerkat`（main 留给上游同步，不要合并）。

## 1. 一次性准备

```bash
# 仓库根目录 E:\projects\meerkatai-agent
npm install
(cd deploy/layers/meerkat/classifier && npm install)
(cd plugins/web-ui && npm install && npm run build)   # 网络受限时加 --proxy http://127.0.0.1:7890 --https-proxy http://127.0.0.1:7890
```

写 `.env`（仓库根，已被 .gitignore 覆盖）：

```dotenv
ORG_ID=meerkat
PORT=8081
HARNESS=pi
ALLOW_UNAUTHENTICATED_CORE=1
CLASSIFIER_URL=http://localhost:8090/classify
CONNECTOR_SECRET_KEY=<随机字符串，固定后不要换>
PI_MODEL=kimi-k3
KIMI_CODE_API_KEY=<你的 Kimi Code key>
```

注意：`CLASSIFIER_URL` 必须带 `/classify` 路径（ADR-009）。key 的命名规则是 `<PROVIDER_ID 大写>_API_KEY`，详见第 2 节「模型配置」。

## 2. 一键启动

```bash
bash scripts/meerkat-local-up.sh   # key 已在 .env 里，脚本自动读取
```

`meerkat-local-up.sh` 用来将配置文件"灌"进正在运行的系统里，可以用它来重启服务。

脚本依次完成：

1. 注册 buildx 插件并（缺镜像时）构建沙盒镜像 `qm-sandbox-base:dev` + `qm-sandbox-local:latest`（首次约 10-20 分钟）；
2. 拉起进程： sidecar(:8090)、core(:8081)、web-ui(:8096)；
3. 注册 `providers/` 下所有供应商、按 `skillpacks.conf` 注册并导入所有 skill pack、按 `models.conf` 设置组织级 base model 和 Web UI 模型列表。
3. 生成路由表。按 `ROUTE_*` 生成 `classifier/local-routes.json` 给 sidecar 用

然后打开 **http://localhost:8096**，任意 id 登录即可使用。

> **为什么 core 重启后必须重跑脚本**：本地部署用内存存储（未接 Postgres），provider 注册、skill pack 导入、组织 base model 都是易失的。脚本是幂等的，重跑即恢复。

### 模型配置

需要更改的配置文件如下：

| 文件名               | 路径                              | 说明                                                         |
| -------------------- | --------------------------------- | ------------------------------------------------------------ |
| `models.conf`        | `deploy/layers/meerkat/`          | 1. 选哪个模型做默认<br />2. 分类器路由指向（MODEL_ID / ROUTE_*） |
| `<provider-id>.conf` | `deploy/layers/meerkat/providers` | 某个供应商的具体配置信息。地址、协议、模型清单（MODELS_JSON） |
| `.env`               | 根目录                            | 各个供应商的 key。属性名为：<PROVIDER_ID 大写>_API_KEY=...   |

#### 换模型

改 `models.conf` 的 `MODEL_ID`（及 `ROUTE_*`），重跑脚本。

#### 换供应商

改 `providers/kimi-code.conf` 里的 `BASE_URL`/`PROTOCOL`/`MODELS_JSON`，`.env` 里换 key，重跑脚本。

#### 添加供应商

在 `providers/` 下新增 `<新id>.conf`（照抄 kimi-code.conf 改内容），`.env` 加一行 `<新ID>_API_KEY=...`，重跑脚本——界面下拉会自动列出所有供应商的模型。

#### 开启语义分类器

数据分级分类器（sidecar）是为了数据隐私安全而开发的。它用来对用户的输入进行数据隐私和敏感性的分类，共有三层机制：

> 第 1 层：PII 正则      → 身份证/手机号/银行卡等硬规则      → 命中即 L1
> 第 2 层：TRIZ 关键词   → 30 个专业词汇表                  → 命中即 L3-triz
> 第 3 层：语义分类      → 调一个小模型"读一遍"内容做判断    → L1/L2/L3 + 领域
>
> L1：高度隐私（禁止出域，只能接本地模型）
>
> L2：中度隐私（安全提示，经用户提醒确认后可以出域）
>
> L3：不涉及隐私（允许直接出域）

分类器流水线 = PII 正则 → TRIZ 关键词 → 语义分类（用本地小模型兜底识别规则认不出的内容）。

**如何开启语义分类器的模型分析能力（第三层功能）**

本地模型就位后，填 `models.conf` 里的 `SEMANTIC_ENDPOINT`（完整的 chat completions 地址）和 `SEMANTIC_MODEL`，重跑脚本即可；留空则该层关闭。脚本启动时会打印 `semantic classifier on/off` 表明当前状态。注意端点需免鉴权（sidecar 请求不带 Authorization 头）。

```tex
# deploy/layers/meerkat/models.conf

# 添加本地模型的地址与名称，然后重跑 meerkat-local-up.sh
SEMANTIC_ENDPOINT=http://127.0.0.1:11434/v1/chat/completions
SEMANTIC_MODEL=qwen3-7b-local
```

### Skills 配置

Skills 以 **skill pack** 形式接入：一个 GitHub 仓库 = 一个 pack。项目里不存放 skills 实体文件，只有一份清单 `deploy/layers/meerkat/skillpacks.conf`：

```bash
SKILLPACKS=(
  "https://github.com/MeerkatAIChina/meerkat-skills-triz.git|main"
)
```

**添加新的 Skills 仓库**：往 `SKILLPACKS` 数组加一行（分支可省，默认 `main`），重跑脚本。

#### Skills 加载与工作机制

脚本把清单里的地址逐个报给 core 注册 + 导入；core 每次导入都会现场从 GitHub 拉取最新内容（读完即删临时文件），所以 skills 更新后只需 push 到仓库、重跑脚本即可生效。断网时该步打 warn 跳过，不影响其余功能启动。

## 4. 进程管理

三个进程都以后台方式运行，日志在 `/tmp/meerkat-{sidecar,core,webui}.log`。停止：

```bash
for p in 8090 8081 8096; do
  PID=$(netstat -ano | grep ":$p" | grep LISTENING | awk '{print $5}' | head -1)
  [ -n "$PID" ] && taskkill //F //PID $PID
done
```

## 5. 已知限制

- **内存存储**：会话、注册信息、审计均不落盘，core 重启即清空（重跑脚本恢复注册，会话不可恢复）。生产部署需接 Postgres（设 `DATABASE_URL` 等，core 侧已支持）。
- **两个路由策略共用同一模型**：微调模型 meerkat-triz-v1 未上线，`local-secure` 与 `meerkat-triz-v1` 暂时都指向 `models.conf` 里的 `ROUTE_MODEL_ID`（当前 kimi-k3）。注意 `local-routes.json` 是脚本**自动生成**的，不要手改；模型上线后改 `models.conf` 的 `ROUTE_*` 重跑脚本即可。
- `ALLOW_UNAUTHENTICATED_CORE=1` 仅限隔离的本机开发，任何可被他人访问的部署都不能开。

## 6. FAQ

以下每条都是本机首次部署时真实遇到并解决的问题，按「你可能遇到的现象 → 原因与解法」组织。

**Q1：我的 `sk-kimi-...` key 调用 `api.moonshot.cn` 一直 401 Invalid Authentication，key 是假的吗？**

不是。`sk-kimi-` 前缀是 **Kimi Code（会员订阅）key**，不是 Kimi 开放平台（按量付费）key，两个平台的 key 不通用。Kimi Code 的 OpenAI 兼容端点是 `https://api.kimi.com/coding/v1`，模型 id 如 `kimi-k2.6`。qm 里注册 custom provider 时 baseUrl 填这个端点即可。

**Q2：登录后第一条消息就 HTTP 403，提示 "that model isn't available on this deployment (its provider isn't configured)"，为什么？**

你落到了组织默认模型 `claude-opus-5`（Anthropic，未配置 key）。组织默认模型在 core 启动时冻结，那时 custom provider 注册表还没水合，`PI_MODEL=kimi-k2.6` 来不及生效。解法：core 起来后用 admin API 持久设置组织级模型——

```bash
curl -X PUT http://localhost:8081/v1/admin/scopes/org:meerkat/base-model \
  -H 'content-type: application/json' -H 'x-admin-actor: admin-alice@meerkat' \
  -d '{"modelId":"kimi-k2.6"}'
```

注意 `PUT /v1/runtime-config` 只允许 personal 作用域，组织级必须走 `/v1/admin/scopes/:scope/:resource`；`x-admin-actor` 的 `@` 后缀必须等于 `ORG_ID`。启动脚本已内置这一步。

**Q3：模型下拉里全是 Fable 5 / Opus 5 之类的内置模型，选中就 403，kimi-k2.6 根本不在列表里？**

两层原因，都要处理：

1. **组织级 `webui-models` 没设**：不设时前端回落到内置默认清单。用 admin API 设置：`PUT /v1/admin/scopes/org:meerkat/webui-models`，body `{"ids":["kimi-k2.6"]}`（脚本已内置）。
2. **前端代码 bug（已修复）**：旧版 `plugins/web-ui/src/pi-models.ts` 的 `getBaseModel()` 不认识 custom provider 模型，构建选项时抛异常，导致即使后端配置正确，下拉也静默回落到内置清单。修复后必须 `npm run build` 重建 web-ui 并重启、强刷浏览器（Ctrl+Shift+R）才生效——只刷新页面加载的还是旧 bundle。

**Q4：沙盒工具报 "SANDBOX_BACKEND=local requires a running Docker daemon"，但 Docker Desktop 明明在跑？**

core 进程的 PATH 里没有 docker CLI。core 通过 spawn `docker` 命令探测 daemon，PATH 找不到就报这个错。解法：启动 core 前把 `C:\Program Files\Docker\Docker\resources\bin` 加进 PATH（启动脚本已内置），并重启 core——daemon 可用性不做动态恢复，必须在 docker 就绪后启动 core。

**Q5：Docker Desktop 一启动就崩溃循环，`~/AppData/Local/Docker/backend.error.json` 涨到 1 GB+，报 "unable to get 'ProgramData'"？**

启动它的父进程环境缺 `ProgramData` 变量（比如从某些精简 shell 里拉起）。解法：从开始菜单正常启动，或显式带上变量：

```bash
ProgramData='C:\ProgramData' nohup "/c/Program Files/Docker/Docker/Docker Desktop.exe" &
```

崩溃期间写出的巨型 `backend.error.json` 可以直接删。

**Q6：构建沙盒镜像时 fly/Dockerfile 第 9 步（下载 gh CLI）失败，提示 `*) exit 1`？**

不是网络问题。默认 `docker build` 是 legacy builder，不提供 `TARGETARCH` 变量，Dockerfile 里的 `case "$TARGETARCH"` 落到 `*) exit 1`。解法：必须用 BuildKit——Docker Desktop 自带 buildx 但没注册到 CLI，先执行：

```bash
mkdir -p ~/.docker/cli-plugins
cp "/c/Program Files/Docker/Docker/resources/cli-plugins/docker-buildx.exe" ~/.docker/cli-plugins/
```

然后用 `docker buildx build --load` 构建（启动脚本已内置这两步）。

**Q7：admin API 返回 404 not_found 或 403 forbidden，路由明明存在？**

两种典型情况：① 404 且不带 message——core 启动版本旧于 `911a787`，该提交修复了 `src/index.ts` 没把 `customProviders` 注入 HTTP deps 的问题，拉最新分支即可；② 403——`x-admin-actor` 头不对，内存模式下用 `admin-alice@<ORG_ID>` 或 `admin-bob@<ORG_ID>`（种子管理员），`@` 后缀必须匹配 `ORG_ID`。

**Q8：npm install / npm run build 网络报错？**

本机有代理（如 127.0.0.1:7890）但 npm 默认不走。显式指定：

```bash
npm install --proxy http://127.0.0.1:7890 --https-proxy http://127.0.0.1:7890
```

**Q9：跑 web-ui 测试套件时有断言失败，是代码改坏了吗？**

先看失败内容。Windows 下 git 默认把文件检出为 CRLF，个别用正则匹配源码换行的测试（如 `expected: /return true;\n\}$/`）会因此失败——这是检出换行符问题，与代码逻辑无关，CI（Linux）不会出现。

**Q10：关机重启后整个系统怎么恢复？**

先启动 Docker Desktop（等 daemon 就绪），再在仓库根执行 `bash scripts/meerkat-local-up.sh`（key 从 `.env` 自动读取，无需手动 export）。脚本会拉起三个进程并恢复全部注册信息；历史会话因内存存储不可恢复。

**Q11：在下拉列表里切了模型，问它"你现在是什么模型"，它却回答另一个模型，切换没生效？**

切换是生效的——模型自己不知道自己是谁。系统提示不会告诉模型它当前运行在哪个模型上，它回答"我是什么模型"时只能瞎猜或读组织默认配置（org 默认模型），不代表本轮真实路由。已用捕获服务器实测验证：选择 `deepseek-v4-pro` 后，请求确实打到了 DeepSeek 供应商端点。想验证切换，别看模型自报，看实际效果（回答风格/速度），或临时把供应商 `BASE_URL` 指向本地捕获服务器观察请求。

另外注意：分类路由会覆盖手动选择，这是设计行为，不是切换失效——TRIZ 关键词命中是**单轮**覆盖为 `classifier/local-routes.json` 配置的模型；PII/敏感内容命中（L1）则将**整个会话单向锁定**到 local-secure 本地模型，之后所有轮都强制走本地、手动切模型不生效（见 Q12）。

**Q12：发过身份证号/手机号之后，这个会话切模型为什么不生效了？**

会话被判定 L1（高度隐私）后会被单向锁定到本地模型：之后所有轮强制走 local-secure，手动选择被忽略，且永不解锁。这是隐私设计——敏感内容已进入会话历史，而每轮请求都携带完整历史，切回云端等于把历史送出域。锁是会话级的，不影响你的其他会话；想用通用模型，另开新会话即可。同理，锁定会话的标题自动生成和记忆捕获也会跳过（它们走 utility 模型，会把内容送出域），所以锁定会话可能一直没有自动标题，属正常现象。
