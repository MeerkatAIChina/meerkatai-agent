# 发布文档

> 如何在一台开发机上从源码构建出 Meerkat 桌面版安装包（v0.1.1-alpha）。本文档的每一步都在 Windows 10（build 19045）上实测通过。与 v0.1 的差异：**多了沙箱 rootfs 构建步骤，前置条件新增 Docker Desktop**。

## 前置条件

| 工具 | 版本 | 说明 |
|---|---|---|
| Node.js | ≥ 24（staging 用 v24.15.0） | 建议装在默认路径 `C:\Program Files\nodejs` |
| Rust 工具链 | stable（rustup 安装） | `~/.cargo/bin` 需在 PATH |
| Visual Studio 2022 Build Tools | "使用 C++ 的桌面开发"工作负载 | Windows 链接器（link.exe）来源，**不装 C++ 负载会报 linker 缺失** |
| Git Bash | 任意 | staging 脚本是 bash |
| npm 依赖 | root 与 `plugins/web-ui` 各 `npm ci` 一次 | 第一次构建前装好 |
| tauri CLI | v2 | `npm i -g @tauri-apps/cli@2`（或 `cargo install tauri-cli --version "^2"`） |
| **Docker Desktop** | 任意（v0.1.1 新增） | **仅构建期需要**：从 Dockerfile 构建沙箱 rootfs。运行安装包的用户不需要 Docker |

macOS 额外需要：Xcode Command Line Tools；mac 构建不出 rootfs（沙箱后端在 macOS 落 `none` 降级）。

## 一次性准备：更新签名密钥

自动更新包需要签名校验。首次生成：

```bash
npm i -g @tauri-apps/cli@2
tauri signer generate -w ~/.tauri/meerkat-desktop.key
```

- 密码可留空（CI/本地构建都以空密码使用）
- **这个私钥一旦更换，老客户端将无法校验新包**，务必备份；公钥已写死在 `src-tauri/tauri.conf.json` 的 updater pubkey 字段，换 key 要同步改它

## 本地构建四步

在仓库根目录执行：

### 1. 构建沙箱 rootfs（v0.1.1 新增）

```bash
bash deploy/layers/meerkat/desktop/scripts/build-rootfs.sh
```

从 `deploy/layers/meerkat/desktop/rootfs/Dockerfile` 构建定制 Debian rootfs（含 Node 与沙箱 agent），导出为 `payload-sandbox/rootfs.tar.gz`（约 148MB）+ `fingerprint.txt`。**需要 Docker Desktop 已启动**。agent 代码（`src/sandbox/` 侧协议或 `agent.mjs` 模板）改动后必须重跑。

### 2. 组装载荷（payload）

```bash
export PATH="$PATH:/c/Program Files/nodejs"
bash deploy/layers/meerkat/desktop/scripts/stage-payload.sh
```

这一步会：拷 Node 运行时 → esbuild 把 core 和 web-ui server 打成单文件 → 构建 web-ui 前端 → classifier 装生产依赖 → 拷种子配置 → **拷 rootfs 进 `payload/sandbox/`**。产物在 `deploy/layers/meerkat/desktop/payload/`（约 300MB）。

脚本幂等，每次先清空旧 payload 重建。改了 `src/`、`plugins/web-ui/`、classifier、种子或 rootfs 后必须重跑。

### 3. 冒烟验证（可选但建议）

```bash
bash deploy/layers/meerkat/desktop/scripts/verify-payload.sh
```

从 payload 直接起 core，跑一轮对话 + 一轮分类路由，确认裁剪没有伤到运行时。

沙箱全链路另有专项 E2E（需要本机已启用 WSL2）：

```bash
export PATH="$PATH:/c/Program Files/nodejs"
node --experimental-strip-types scripts/test-wsl2-e2e.ts
```

真实导入测试 distro，覆盖 rootfs 导入、agent 拉起、exec 读写、出网围栏（白名单内 200 / 白名单外 403 / 绕过 DROP）共 11 项。

### 4. Tauri 打包

```bash
cd deploy/layers/meerkat/desktop
export PATH="$HOME/.cargo/bin:$PATH:/c/Program Files/nodejs"
export TAURI_SIGNING_PRIVATE_KEY="$(cat ~/.tauri/meerkat-desktop.key | tr -d '\r\n')"
export TAURI_SIGNING_PRIVATE_KEY_PASSWORD=""
MSYS2_ARG_CONV_EXCL="*" tauri build
```

产物：

```text
src-tauri/target/release/bundle/nsis/Meerkat_0.1.1-alpha_x64-setup.exe      ← 安装包（约 192MB）
src-tauri/target/release/bundle/nsis/Meerkat_0.1.1-alpha_x64-setup.exe.sig  ← 更新签名
```

`build.rs` 会检查 payload 是否存在——没跑第 2 步直接 `tauri build` 会在 release 模式下直接报错。

## 版本号与发布

- 安装包版本号来自 `src-tauri/tauri.conf.json` 的 `version` 字段，发新版前先改它（本次为 `0.1.1-alpha`），否则覆盖安装判定会混乱
- 发布形式：GitHub Release（tag `v0.1.1-alpha` + What's Changed + 安装包与 .sig 附件），参照 v0.1.0-alpha 的发布；对外分发再把安装包转存到客户可达的渠道

## 踩坑记录

1. **`tauri build` 超时被杀**：cargo 全量编译 Rust 依赖要几分钟。构建是**增量**的，超时后原样重跑同一命令即可续编，不会从头再来
2. **报 linker / `link.exe` 缺失**：VS Build Tools 没装 C++ 工作负载。装完后如果还报，先跑 `scripts/cargo-msvc.bat` 再构建
3. **payload 旧了**：表现是"装了新包但行为没变"。`stage-payload.sh` 必须在每次代码改动后重跑，tauri build 不会自动重建 payload
4. **rootfs 旧了**：表现是"沙箱行为没跟着代码变"。`build-rootfs.sh` 改了 agent/Dockerfile 后要重跑，且要在 `stage-payload.sh` **之前**跑
5. **签名 key 路径含 `\r`**：Windows 下私钥文件可能带 CRLF，`cat | tr -d '\r\n'` 这步不能省，否则签名校验静默失败
6. **rootfs 构建拉镜像慢**：Debian 基础镜像拉取受网络影响，必要时给 Docker Desktop 配镜像加速或代理
