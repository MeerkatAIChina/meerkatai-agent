# v0.1.1 设计文档

## 概述

落地需求二：Windows 桌面版获得自研沙箱（WSL2 底座），execute/write/read 等沙箱工具从"不可用"变为"内置可用"。macOS 本期保持 v0.1 的降级行为，srt backend 设计封存、零代码。

前置文档：《需求调研.md · 需求二：桌面化的沙箱》（`docs/meerkat/v0.1/需求调研.md:97`）——三个候选底座的核实与评估结论本文不再重复，直接采用其推荐架构。

核心决策一览：

| 决策点 | 结论 |
|---|---|
| 平台范围 | 设计双平台，实现只做 Windows。macOS 不做接口预留——`Sandbox` 接口本身就是预留，加后端 = 联合类型加值 + config 枚举 + wiring 分支三处加法 |
| WSL2 启用路径 | 安装器不动 → 首启设置页授权（一次 UAC）→ rootfs 导入挂启动清单。否决"安装器内闭环"（安装器需变机器级 + RunOnce 重启续跑，且 UAC 弹在用户不理解为何弹的语境里） |
| rootfs 分发 | 随包内置 tar.gz（≤110MB 压缩），更新 = 随 app 发版 + 指纹重导入。否决首启下载（版本错配风险：agent.mjs 与 core 有隐式版本契约） |
| 出网策略 | domain 白名单（分层围栏 + 开工前 spike，见第五节）。默认放行公网已否决（否决记录进 ADR） |
| 传输层 | guest agent over localhost 转发。agent.mjs 是 qm 沙箱的协议本体（aws/local 共用），选它 = WSL2 后端第一天起进入"已验证行为集合"。否决 wsl.exe 薄传输（冷启动税 50-300ms/次 × 高频调用、进程会话语义塌缩、stdout 二进制边界问题）与混合双通道（无事务边界的一致性 bug） |

## 第一节：整体架构

```text
Tauri 壳（新增职责）
  ├─ 沙箱基础设施：WSL2 状态探测 → 设置页授权启用 → rootfs 导入/指纹校验（启动清单"沙箱"行）
  └─ proc.rs：按平台映射表注入 SANDBOX_BACKEND

core（纯加法）
  ├─ SandboxBackendName：+ "wsl2" | "none"
  ├─ config.ts：枚举 + 校验
  ├─ wiring.ts：buildWsl2 分支
  └─ wsl2-sandbox.ts：Sandbox 接口实现 ──HTTP──▶ WSL2 guest agent（agent.mjs）
                                                  ├─ 复用 exec-file-ops / exec-process-session / exec-backup 全套辅助层
                                                  └─ workspace = guest ext4 内 per-scope 目录（vhdx 持久，重启不丢）
```

平台映射表（proc.rs 注入）：

| 平台 / 状态 | SANDBOX_BACKEND |
|---|---|
| Windows + rootfs 已导入 | `wsl2` |
| Windows 未启用 WSL2 / 未导入 | `none` |
| macOS | `none`（产品文案"沙箱能力即将支持该平台"） |

`none` 不是"不构造后端"，而是一个显式 stub：`provision()` 直接报"沙箱不可用"的清晰错误——替代 v0.1 借 `local` 后端、Docker 缺席时在 preflight 才炸的扭曲。

`SandboxBackendName` 只加实际实现的 `"wsl2"`（与 `"none"`）；`"srt"` 一行代码不写，见第六节。

## 第二节：core 侧 wsl2 backend

### 传输

core 打 `http://127.0.0.1:<动态端口>`（WSL2 localhost 转发，Win10 21H2+ 默认开启）。端口由 core 侧分配注入（沿用动态端口哲学，避开 8080 这类易撞端口）。备用路径：`wsl hostname -I` 拿虚拟网卡 IP——仅作 FAQ 级降级，主路用 localhost。

**guest agent 必须 bind `0.0.0.0` 而不是 `127.0.0.1`**，否则 WSL2 的 localhost 转发够不到它（经典踩坑点；agent.mjs 现状即 bind 0.0.0.0，保持不变）。

### 生命周期

```text
core 启动
  ├─ wsl -d meerkat-sandbox -- exec true   ← 探活并唤醒 VM
  ├─ agent 未跑 → 拉起（AGENT_PORT 注入动态端口 + 认证 token，见第九节）
  ├─ 健康轮询 GET /health（timeout 10s）
  └─ ready / 失败 → onError + 沙箱工具不可用（fail-closed 呈现，见第七节）

app 退出：不管 shutdown——WSL2 空闲 VM 自动回收
```

### 接口供给

agent 的 `/exec` `/write` 恰好供给 `exec` + `writeInline` 原语对，文件操作 / 进程会话 / home 备份全套复用 `exec-file-ops` / `exec-process-session` / `exec-backup` 辅助层。行为与 aws/local 生产后端对齐——云端复现的 bug 在桌面必现，测试用例可跨后端跑。

能力声明：

| 能力 | 首版 | 说明 |
|---|---|---|
| 必须项（provision/run/read/write/listDir/removeDir/teardown） | ✅ | |
| process sessions | ✅ | `profile.processSessions = true` |
| home backup | ✅ | 复用 `createExecBackup` |
| blob staging（stageIn/stageOut/extractFiles） | ❌ | 对齐 local Docker 后端先例（local-sandbox.ts 从未实现）；stageIn 唯一调用方是 sandbox-migrate 跨后端迁移，桌面无此场景 |
| egressEnforcement | `"domain"` | 见第五节 |

### 版本契约

复用镜像指纹思路（`computeSandboxImageFingerprint`，`local-sandbox.ts:54`）：rootfs 导入时把 agent 指纹写进元数据，app 升级后指纹不匹配 → 触发重新导入。"rootfs 随 app 版本走"在此闭环。

## 第三节：rootfs 构建、分发与更新

### 内容清单

| 组成 | 压缩后（估） |
|---|---|
| Debian minbase rootfs（debootstrap 精简变体） | ~35-50MB |
| Node 24 Linux x64（仅 `node` 二进制，不要 npm） | ~25MB |
| agent.mjs + 沙箱工具链（python/pandas/git/curl 等，对照 `fly/Dockerfile` 清单） | ~20-40MB |
| **合计** | **~80-110MB** |

rootfs 不是随便一个 Linux 系统，内容清单可控；它不是知识包那种"内容持续演进"的东西，跟着代码走——与"知识包不内置"原则不冲突（rootfs 是运行环境不是内容，与 payload 内置 Node 运行时同一范畴）。

### 构建与分发

- 构建脚本进 `deploy/layers/meerkat/desktop/scripts/`（debootstrap 或基于 `fly/Dockerfile` 工具清单制作），构建时算指纹写进 rootfs 元数据
- 随包进 payload，`wsl --import meerkat-sandbox <DATA_DIR>/wsl/ rootfs.tar.gz` 一次性导入——**不需要管理员**（WSL 发行版是用户级的），`wsl --import` 直接吃 tar.gz
- 安装包体积预算：当前 37MB + rootfs 后约 110-150MB，体积目标从 v0.1 的 <400MB（压缩前口径）修正为 **<200MB（压缩后实测口径）**

### 更新

更新通道 = app 发版：app 升级后指纹不匹配 → 启动清单"沙箱"行显示"更新中" → 后台重新导入。不建独立更新通道，杜绝"app v0.1.2 + rootfs v0.1.0 的旧 agent"的版本错配。

## 第四节：WSL2 检测/启用/导入流程

三步的权限和体感完全不同，不绑在一起处理：

| 步骤 | 权限 | 耗时 | 体感 |
|---|---|---|---|
| 检测 WSL2 状态 | 无 | 毫秒 | 无感 |
| 启用 WSL2（`wsl --install` / dism 开虚拟机平台） | **管理员（UAC）+ 可能要重启** | 分钟级 + 重启 | 重型断点，一次性、机器级 |
| 导入 rootfs（`wsl --import`） | 不需要管理员 | 秒级~30s | 轻，可后台 |

启用是唯一需要用户做决定的点（UAC 弹窗必须出现在用户理解为什么弹的语境里）；导入是纯体力活，不需要出现在任何用户界面上。

### OS 门槛

`wsl --install` 一键启用要求 **Win10 2004+（推荐 21H2+）**；更老的 Win10 要走 dism 手动两步。新增的 WSL2 状态探测 command 必须同时查出 OS build 号——低于门槛直接走"机器不支持"降级文案，不引导用户去撞手动流程。

### 流程

```text
安装器：什么都不做（或仅一行提示）。保持用户级、快速、无 UAC

首启设置页（现有三区块旁加第四区块「沙箱」）：
  ├─ 检测已启用 → 显示"✅ 沙箱已就绪"（导入在后台静默完成）
  ├─ 未启用 → 显示说明 + [启用沙箱] 按钮
  │     点击 → Tauri command → ShellExecute runas 弹一次 UAC
  │     → 需要重启：页面显示"重启电脑后生效"，并记住状态
  │     → 不需要重启（部分 Win11 新 build）：直接进导入
  └─ 用户拒绝/跳过 → 明确标注"沙箱不可用，代码执行类功能将关闭"
       （v0.1 的 fail-closed 降级，对话/路由不受影响）

启用成功后的每次启动：
  └─ 启动清单加一行「沙箱」：rootfs 未导入 → 黄灯"初始化中"（后台导入，
     秒级~30s 可等完）；指纹不匹配 → 黄灯"更新中"；完成 → 绿灯
     绝不推迟到"首次使用沙箱时"——对话中途冒出 30 秒不可预期等待是最差的时机
```

### 新增 Tauri commands

| command | 职责 | WebView ACL |
|---|---|---|
| `wsl2_status` | 探测 WSL2 状态 + OS build 号 + rootfs 导入状态 | web-ui 来源放行（设置页要查） |
| `enable_wsl2` | ShellExecute runas 启用 WSL2（一次 UAC） | web-ui 来源放行（设置页按钮） |

两份 capabilities 清单收口，沿用 v0.1 设计文档第八节的双清单机制（本地 splash 全量 / web-ui 按需放行）。

## 第五节：网络策略（domain 白名单）

### 为什么是白名单，而不是放行公网

隐私承诺链：

```text
L1 内容 → 锁本地模型 → 历史不外发
```

沙箱是这条链的侧门：L1 会话的工作区里就是敏感文件，而沙箱里跑的是模型现场生成的脚本。沙箱默认自由出公网 = 一段被 prompt 注入诱导（或单纯犯错）的脚本就能把本地模型的隐私保证打穿——**本地不本地，出网不出网，缺了任何一半，隐私承诺都不成立**。默认放行公网已否决，否决记录进 ADR，防止以后图省事加回来。

白名单同时是产品声明：内置 pypi/npmjs/github 等常用源，等于把"沙箱只能和这些地方说话"写进产品边界，客户的安全评审看得懂、过得去。

### 分层围栏 + 开工前 spike（必修）

"宿主机 WFP 规则拦死 WSL2 直连 NAT 出口"目前是一个**有疑点的假设**：WSL2 流量走 Hyper-V 虚拟交换机 NAT，不是宿主机用户态进程发出的，WFP 用户态过滤规则默认管不到 VM 内部发出的包；`.wslconfig` 的防火墙集成（Hyper-V 防火墙规则作用于 WSL2 流量）是 Win11 22H2+ 才有的路，而产品明确支持 Win10。

因此本节设计为三层，开工前先 spike：

1. **guest iptables（内层）**：rootfs 是我们做的，规则内置。但 agent 在沙箱里是 root，理论上可被 flush——它是"内层"不是"围栏"
2. **宿主机防火墙按平台能力分层**：Win11 22H2+ 用 Hyper-V 防火墙集成；Win10 走 vEthernet 接口规则或 HNS 策略
3. **spike 先行**：验证"Win10 上到底能不能拦死 WSL2 直连"。spike 结论决定本节最终形状——**拦不死就触发 fallback（无网络档），不允许实施中静默降级**

### 形状

- 宿主机（Windows）侧跑过滤代理，guest env（`HTTP_PROXY` 等）指向代理；围栏必须在代理外面，否则 `unset HTTP_PROXY` 即绕过
- 白名单内置 pypi/npmjs/github/常见镜像源，随种子下发；设置页可改列入二期
- 与 macOS 路线同构：srt 的网络隔离就是宿主机代理 + 域名白名单，二期做 macOS 时心智模型统一，部分代码可复用

### 显式 fallback：无网络档

工期吃紧或 spike 证明 Win10 拦不死时，退"沙箱无出网"档：rootfs 预装全部工具链（python/pandas 等），"现场 pip install"这类锦上添花的能力失效，主链路（资料查找 + 报告生成）杀伤力有限。产品文案"沙箱为离线隔离环境"。触发条件写进执行计划，**不允许实施中静默降级**。

## 第六节：macOS 设计封存

srt backend 形状记录备二期：

- `SandboxBackendName + "srt"`，core/config/wiring 三处加法
- 形态：Seatbelt 动态 profile 包裹宿主机进程，workspace = DATA_DIR 下真实目录，文件系统默认只读/工作区可写
- 复用同一套 `exec-file-ops` / `exec-process-session` 辅助层（macOS 自带 bash/tar/sysctl，POSIX 契约成立）
- 网络白名单与第五节同构（宿主机代理 + 域名白名单）

本期零代码。"为 macOS 预留接口"不需要专门设计任何东西——`Sandbox` 接口就是接口，不预留就已经预留了。本期 mac 上 execute 工具不可用（与 v0.1 现状一致），产品文案统一为"沙箱能力即将支持该平台"。

## 第七节：降级与失败分级

沙箱永远不是启动致命项：

| 情况 | 级别 | 行为 |
|---|---|---|
| 用户拒绝/跳过启用 WSL2 | 降级 | fail-closed：execute 类工具不可用，对话/路由完整（v0.1 现状行为），设置页常驻引导 |
| 机器不支持（OS build 低于门槛 / 企业策略禁虚拟化 / 旧 CPU） | 降级 | 同上，文案"此机器不支持沙箱" |
| rootfs 导入中 / 更新中 | 黄灯 | 启动清单显示"初始化中"/"更新中"，可等完（秒级~30s），放行进主界面 |
| agent 崩溃 | 降级 | core watch 检测 + 拉起一次；拉不起来则沙箱工具报错，对话不受影响 |

二期评估 srt-win 作为"WSL2 不可用机器"的候选降级（需另写 cmd 形状的执行层，工作量不小）。

## 第九节：安全

### guest agent 认证（内核缝，进 ADR）

localhost 转发意味着本机任意进程可打 agent 端口 = 以 root 在沙箱内执行任意命令、读取含敏感材料的 workspace。core 首启生成 per-boot token，拉起 agent 时注入 env，请求带 header 校验——与 `CORE_SIGNING_SECRET` 同一威胁模型纪律。

**内核缝标注**：agent.mjs 当前没有认证机制（云端靠网络命名空间隔离），且是 aws/local 后端共用的共享文件。token 校验必须做成 **env 可选开启、默认关闭**，保持其他后端行为不变——这条进 ADR 的内核缝清单（对齐 v0.1 的三处内核缝先例）。

### workspace 隔离

workspace 在 guest ext4 vhdx 内，不出现在 Windows 文件系统——本机其他进程不经 agent 够不到沙箱内容。

### 网络围栏

见第五节（分层围栏：guest iptables 内层 + 宿主机防火墙按平台分层）。

## 第十节：测试与验收

### 单测

- wsl2 backend 走 Sandbox 接口契约测试，复用 local 后端的测试形状（同一份用例跨后端跑）
- config 枚举 / wiring 装配分支 / none stub 的 provision 报错
- agent token 认证：默认关闭（aws/local 行为不变）+ 开启后校验生效

### 真机验收三路径

| 路径 | 验收点 |
|---|---|
| 全新 Win10/Win11（未启用 WSL2） | 设置页授权 → UAC → 重启 → 后台导入 → 绿灯 → execute 工具可用 |
| 已启用 WSL2 | 直接后台导入 → 绿灯 |
| 禁用虚拟化的企业机 / OS 低于门槛 | 降级路径，文案正确，对话/路由不受影响 |

### 网络围栏验证

白名单内 `pip install` 成功 + 白名单外域名直连被拦死 + `unset HTTP_PROXY` 绕过尝试失败。（spike 若证明 Win10 拦不死，本项按无网络档重定义。）

## 第十二节：不做

- 不做 macOS srt backend 代码（设计封存，接口天然预留，二期直接补）
- 不做 srt 相关的一切依赖、Seatbelt profile、Windows alpha 跟踪（一行代码不写）
- 不做设置页白名单编辑（二期）
- 不做 WASM 兜底（调研已否决：跑不了"现场写脚本再执行"语义）
- 不做 srt-win（二期评估，需 cmd 形状执行层）
- 不做安装器内启用 WSL2（UAC 语境错误 + RunOnce 重启续跑复杂度 + 安装器需变机器级）
- 不做 blob staging（对齐 local 后端先例，迁移场景桌面不存在）
- 不做分离的 rootfs 更新通道（更新 = app 发版 + 指纹重导入）
- 不做 rootfs 首启按需下载（版本错配风险）
