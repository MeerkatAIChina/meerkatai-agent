# v0.1 设计文档

## 概述

将 meerkat 的三进程 localhost 拓扑封装为跨平台桌面应用，用户无需安装 Node、Docker 或配置环境变量。

核心路线：**Tauri v2 壳 + 随包 Node 运行时 + sidecar 三进程**。Tauri 官方有 Node sidecar 专项指南，本项目的三进程拓扑与该模式天然匹配。

桌面版与本地开发模式的关键差异：

| | 本地开发 | 桌面版 |
|---|---|---|
| 启动方式 | `bash scripts/meerkat-local-up.sh` | 双击图标，清单式启动 |
| 端口 | 固定 8090/8081/8096 | Rust 选空闲端口动态注入 |
| 存储 | 无 Postgres → 内存（重启丢会话） | SQLite（全持久化） |
| 认证 | 无认证绑 localhost | `CORE_SIGNING_SECRET` + 全链签名 |
| 配置 | `.env` + `providers/*.conf` 手动编辑 | 种子内置 + 首启设置页填令牌 |
| 沙箱 | Docker 可选 | 无（等待需求二自研沙箱） |

## 第一节：整体架构

### 进程拓扑

```text
┌─ Tauri v2 壳 (Rust) ───────────────────────────────────────────┐
│  main.rs                                                        │
│  ├─ 端口分配（动态选空闲端口）                                    │
│  ├─ 进程管理（spawn → 健康轮询 → watch 存活）                     │
│  ├─ 首启引导（bootstrap：查 provider 状态 → 分流设置页/主界面）    │
│  ├─ 窗口生命周期（清单 splash → WebView → 崩溃拦截页）            │
│  └─ 自动更新（tauri-plugin-updater）                             │
│                                                                 │
│  ┌─────────────────── sidecar 进程 ───────────────────────┐     │
│  │ classifier :$PORT     Fastify, PII/TRIZ/语义三层        │     │
│  │ core :$PORT           qm 核心 API + orchestrator        │     │
│  │ web-ui :$PORT         Node HTTP server + dist-web/      │     │
│  └────────────────────────────────────────────────────────┘     │
│                                                                 │
│  WebView ──$CORE_SIGNING_SECRET──▶ web-ui ──签名──▶ core        │
└─────────────────────────────────────────────────────────────────┘
```

三个进程共享一个 Node 24 运行时（打包进 `payload/node/`），TS 源码直跑，无需预编译。进程启动顺序：classifier → core → web-ui。core 不依赖 classifier（fail-to-local 设计下 classifier 宕机不影响 core 启动）；web-ui 依赖 core 就绪。

### 端口动态分配

Rust 启动时为三个端口各调用 `TcpListener::bind("127.0.0.1:0")` 获取空闲端口，通过环境变量注入子进程：

| 环境变量 | 进程 |
|---|---|
| `PORT` | classifier |
| `PORT` | core |
| `PORT` + `CORE_API_URL` | web-ui（`CORE_API_URL=http://127.0.0.1:$CORE_PORT`） |

core 读 `PORT` env（`src/config.ts:699`）；classifier 同理。web-ui 通过 `CORE_API_URL` 指向 core 动态端口。

固定端口是本地开发时代最常见的启动失败原因。动态分配后"端口被占用"从故障清单中永久抹掉。

### 进程生命周期

```text
启动
  │
  ├─ 1. 分配端口 → 注入 env
  ├─ 2. spawn classifier → 轮询 GET /health (timeout 10s)
  ├─ 3. spawn core → 轮询 grep 日志 "listening on" 或新增 GET /health (timeout 30s)
  ├─ 4. spawn web-ui → 轮询 GET /healthz (timeout 10s)
  ├─ 5. WebView 指向 http://127.0.0.1:$WEBUI_PORT
  │     └─ web-ui 层 bootstrap 检查 provider 注册状态
  │          ├─ 空 → 重定向到设置页路由 /setup
  │          └─ 已有 → 重定向到主界面
  │
  └─ 注：core 当前无 /health 端点（up 脚本靠 grep 日志判断就绪），需补一个轻量端点或沿用 grep

运行期
  │
  ├─ watch 子进程存活
  │   ├─ core/web-ui 死亡 → 切到"服务中断，正在重启"页 + 自动拉起一次
  │   └─ classifier 死亡 → 降级提示，不阻断主流程（见第五节失败分级）
  └─ 窗口关闭 → SIGTERM 三进程 → 回收

托盘（v0.1 不做）：关窗最小化到托盘、后台驻留。Meerkat 是窗口应用，用完即关；托盘后续版本再加。
```

## 第二节：存储面

### 硬约束：会话与锁必须同后端

会话持久化和锁持久化必须同生同死——要么都内存，要么都 SQLite。

如果会话进了 SQLite 但锁留在内存：重启后 L1 会话的敏感历史还在磁盘上，锁却丢了。下一轮重新分类时，分类器只看"新输入 + 最近 3 条历史"（16k 截断），窗口之外的旧敏感内容看不见 → 该轮路由到云端 → 完整历史重放 → 泄漏。

### SQLite 替代 Postgres

桌面版没有 Postgres。用 Node 24 原生 `node:sqlite` 替代。改动边界：

| 组件 | 现状 | 桌面版 |
|---|---|---|
| `SessionStore` | `createPostgresSessionStore` / `createMemorySessionStore` | 新增 `createSqliteSessionStore` |
| `DurableMap`（~50 处） | `pgArtifactMap.map<T>(table)` / `createMemoryMap<T>()` | 新增 SQLite backend |
| `sessionLockStore` | `artifactMap<T>("session_locks")`（v0.0 定义接口） | 同上，自动走 SQLite |

`createSqliteSessionStore` 和 SQLite `DurableMap` backend 是 v0.1 的基础设施新增，不属于 Tauri 壳范畴。它们替换的是 wiring.ts 里的后端选择分支，桌面版编译时或运行时选择 SQLite。

### 数据目录

`DATA_DIR` 指向 OS 应用数据目录（通过 Tauri path API 获取并注入 env），与安装目录彻底分离：

- Windows: `%APPDATA%/Meerkat/`
- macOS: `~/Library/Application Support/Meerkat/`

覆盖安装时安装目录被替换，但 DATA_DIR 分毫不受影响——更新流程因此零迁移逻辑。

### 存储内容

```
DATA_DIR/
├── meerkat.db              ← SQLite（会话 + 锁 + 配置 + skills 元数据）
├── secrets.json            ← 首启生成的全部 secret（connector/signing/portal/skill/capability），ACL 限当前用户
├── local-model.json        ← 本地模型配置（设置页写入，classifier 热加载）
├── network.json            ← 网络代理配置（设置页写入，可选）
├── skills/                 ← skill pack 物化文件
├── workspaces/             ← 会话工作区
└── logs/                   ← 进程日志（诊断用）
```

## 第三节：首启引导与密钥配置

### 方案定位

安装包内置**无秘密的供应商目录**（种子），首次启动用一个**极简页面**收服务令牌和本地模型 endpoint——云端模型的真实 key 全部留在 tensoris 账号后面，桌面只持有按客户签发的令牌。

### 种子配置（安装包内置，只读）

打包进 `payload/config/`：

| 文件 | 内容 | 含秘密？ |
|---|---|---|
| `seeds/providers.tensoris.json` | provider 元信息（name/protocol/baseUrl）、模型清单 | 无 |
| `seeds/providers.local-secure.json` | 本地隐私模型协议与模型清单，baseUrl 留占位 | 无 |
| `seeds/routes.json` | L1 → local-secure、TRIZ → meerkat-triz-v1 的路由映射 | 无 |
| `seeds/defaults.json` | 默认模型 id、webui-models 清单 | 无 |

生命周期：种子内容 = 厂商产品配置，发版时随安装包更新；用户永不需要打开它。

运行时衔接：Rust 启动 classifier 时注入 `ROUTES_PATH` 环境变量，指向 `payload/config/seeds/routes.json`（只读），classifier 从该路径加载路由映射。

### 首启设置页（web-ui 内路由）

设置页作为 web-ui 内的一个路由（如 `/setup`），由 web-ui server 直接服务。web-ui 持有 `CORE_SIGNING_SECRET`，可代签 admin API 调用（通道现成，与现有 `/api/*` 代理同构）。

触发条件：web-ui 启动后，bootstrap 中间件检查 core 的 provider 注册状态——无任何已注册 provider 时 HTTP 重定向到 `/setup`；已有则放行到主界面。

页面只有三个区块：

1. **服务令牌**（必填）：输入框 + "验证并保存"。点击后桌面用该令牌对 tensoris 发一次 `GET /models`，通过后调 `/v1/admin/custom-providers` 完成注册——先验证后入库，杜绝存错令牌后对话报错
2. **本地模型 endpoint + 密钥**（选填）：客户内网 vLLM/Ollama 地址（如 `http://192.168.x.x:8000/v1`），带连通测试。未填则 L1 路由目标缺失——隐私设计下这是阻断而非降级（fail-to-local 失败即拒答），页面需明确提示"未配置时涉敏内容将无法回答"
3. **网络代理**（选填，实施中新增）：如 `http://127.0.0.1:7890`，用于 skill pack 的 GitHub 拉取走代理（core 默认出于 SSRF 防护禁用一切代理，见 ADR-008）。保存后写入 `DATA_DIR/network.json` 并由 Tauri 壳重启 core 生效
4. **高级**（折叠，v0.1 不做）：BYOK、自定义供应商

存储：令牌经 admin API 进 core 的加密存储（connector secret 加密）；endpoint 注册为 local-secure provider 的 baseUrl。两者随 SQLite 持久化，一次填写永久有效。

### 令牌供应链（tensoris 控制台，零新增服务端）

```text
厂商（tensoris 控制台）
  └─ 每个客户交付时：新建令牌
       命名"客户A" · 设额度上限 · 设有效期 · 按需限定模型
       └─ 令牌字符串随交付包发给客户（邮件/交付函/实施人员现场）
```

- 计量：控制台按令牌出用量统计 = 现成的按客户计费依据
- 吊销：客户流失/令牌泄漏 → 控制台一键禁用，即时生效
- 轮换：到期前新建令牌发给客户，客户在设置页换新。真实上游 key 厂商想换就换，客户无感

### 首启流程

```text
首次启动：
  分配端口 → 拉起 classifier → 拉起 core → 拉起 web-ui
  → WebView 打开 → web-ui bootstrap 查 provider 注册状态（空）
  → 重定向到 /setup
  → 用户填令牌 (+endpoint) → 连通验证 → 注册 provider/默认模型/路由
  → 导入 skill packs → 重定向到主界面

后续启动：
  分配端口 → 拉起 classifier → 拉起 core → 拉起 web-ui
  → WebView 打开 → web-ui bootstrap 查 provider 注册状态（已存在）
  → 幂等校验（skills 更新检测）→ 直接进主界面
```

bootstrap 从"每次全量重建"变为"首启建一次，之后只做校验"。启动不再依赖配置文件每次重写注册。

### 安全配套

1. **稳定 connector secret**：首启生成随机 32 字节密钥，存 `DATA_DIR/connector-secret.bin`（文件 ACL 限当前用户，权限 0600），注入 `CONNECTOR_SECRET_KEY` 环境变量——没有这个，加密令牌在 SQLite 里重启即报废（现状兜底是进程级随机密钥）
2. **本机访问控制**：core 只绑 127.0.0.1 + 启用 `CORE_SIGNING_SECRET`（首启随机生成），界面 ↔ web-ui ↔ core 全链签名，本机其他进程调不动 core API

### 边界情况

| 情况 | 行为 |
|---|---|
| 首启不填令牌直接关窗 | 下次启动再弹；不填用不了云端模型（本地模型配了可纯本地使用） |
| 令牌填错/过期/被吊销 | 验证步骤当场报错提示，不会入库 |
| 使用中被吊销 | 对话报错时可在设置页换新令牌 |
| 令牌到期前 | v0.1 提供"更换令牌"按钮；后续增强显示剩余额度/有效期 |
| 离线客户 | 令牌是字符串，交付函附上即可，全程无需在线握手 |
| 本地 endpoint 未配 | 涉敏输入直接拒答并提示（fail-closed），界面引导去设置页 |

## 第四节：Skill Packs 分发

### 主通道：在线拉取（实施定稿）

种子新增 `seeds/skillpacks.json`（pack 清单：url + ref + 可选 `local: true`）。**web-ui 启动任务**（`ensureSkillPacks`）负责落地：等待桌面登录 token 与 core 管理员就绪 → 按 url 去重 → 未注册则注册 → 统一 `import selected:"all"` 调和——**每次启动都重新拉取 reconcile**，即"静默升级"由启动时 reconcile 实现（初稿的 `updateAvailable` 后台检测未单独实现）。失败按 10s/30s/60s 退避重试 4 次，下次启动再试；导入成功一次即 SQLite 持久化。

两个实施期发现并解决的问题：

1. **鉴权**：core 在生产模式下要求 `/v1/admin/*` 携带已验证 portal 身份，启动任务必须等 token 出现后带 token 调用（`fe5f94c`）
2. **网络**：core 的 pack-fetcher 出于 SSRF 防护禁用一切代理，国内直连 GitHub 不稳定 → 新增显式开关 `SKILL_PACK_GIT_PROXY`（ADR-008），桌面端由设置页"网络代理"字段写入 `network.json`、Tauri 壳重启 core 生效

### 兜底通道：交付分发

知识包文件与令牌一样走交付渠道（交付函/U盘/实施人员），与安装包彻底分离。**设置页"导入知识包"入口 v0.1 未做（转入遗留清单）**；技术通道已具备——seed 的 `local: true` 条目可按本地仓库路径注册（`allowLocal` 受控通道，见下）。

### 企业变体：内网镜像（可选，不做承诺）

有 git 基础设施的客户可把 Skills 仓库镜像到内网，种子配置指向内网地址，恢复"在线拉取"体验且不出域。

### 技术前提（已落地）

core 的受控本地导入通道：`ALLOW_LOCAL_SKILL_PACKS=1` + 注册时 `allowLocal: true` 且 url 为本地路径才放行（`89c227d`），桌面 production 模式下默认的 `allowLocalRepos` 仍然关闭。

### 启动降级

知识包未导入不阻断启动。启动清单黄灯"知识包未安装"，进主界面后对话正常、TRIZ 回答退化，下次启动自动重试。导过一次之后黄灯永久消失。

## 第五节：启动体验

### 清单式启动页

启动页本身即是状态清单——Rust 轮询到什么就显示什么：

```text
┌──────────────────────────────┐
│   Meerkat 正在启动…           │
│                              │
│   ✅ 分类器    就绪 (2s)      │
│   ✅ 核心服务  就绪 (6s)      │
│   ⏳ 知识包    加载中…        │
│   ⬜ 界面                     │
└──────────────────────────────┘
```

逐项点亮，全部绿自动进主界面。某项红了：就地显示用户可读的原因 + 重试按钮 + "复制诊断信息"（一键复制进程日志摘要，发给售后即定位）。这不是额外窗口，就是 splash 本身。

### 失败分级

不是所有红都阻断启动：

| 级别 | 组件 | 行为 |
|---|---|---|
| 致命（红） | core / web-ui | 阻断 + 显示错误原因 + 重试按钮 |
| 致命（红） | classifier 宕机 + 本地模型未配 | 全部问答阻断（无法证明非敏感即按敏感处理，fail-closed），引导去设置页配本地 endpoint |
| 降级（黄） | classifier 宕机 + 本地模型已配 | 全部流量降级走本地模型，提示"安全检测暂时不可用，当前仅限本地模型" |
| 降级（黄） | skill packs 拉取 | 提示"知识包暂不可用，将后台重试"，放行进主界面 |
| 降级（黄） | 本地模型 endpoint 不通 | 提示"涉敏问答暂不可用"，放行——它只在使用 L1 能力时阻断单条消息，不该堵启动 |

黄色项不堵主流程，但在设置页常驻引导完成配置。

### 运行期崩溃恢复

core / web-ui 进程中途死亡 → Rust watch 检测 → WebView 切到"服务中断，正在重启"页并自动拉起一次，拉不起来再报错。classifier 死亡 → 降级提示，不切换页面。这套逻辑与启动清单共用同一套状态机。

## 第六节：构建与打包

### 载荷裁剪策略

目标：安装包 < 400MB（当前全量 1.9GB）。

**Stage 0 — 实测**（先跑数字，别猜）：

```bash
# 三份 staging 各跑 npm ci --omit=dev，du -sh 看真实数字
```

如果 Stage 0 结果直接 < 400MB，后续阶段不登场。这个实验半小时跑完，立刻把 5-8 人日的估算压实。

**Stage 1 — A（生产依赖 + 排除已知大头）**：

`npm --omit=dev --omit=optional` + 排除运行时不可达的已知资源：
- `pi-coding-agent` 内含的 TUI 原生预编译（headless core 不需要，按平台排除）
- `emoji-datasource` 原始数据等大型静态资源

约束：Slack/AWS 等 connector 依赖不能简单 `rm -rf`——orchestrator 顶层静态 import 了 connector 模块（`mergeConnectors(RESIDENT_AUTH_CONNECTORS, ...)`），文件没了启动直接崩。要真剔除得改 core 的加载方式，那是 v0.1.x 的优化，不进首版。

**Stage 2 — B（esbuild 精准瘦身）**：

仅当 Stage 1 仍超标时启用。对 core 单入口用 esbuild 打一个 bundle——一个入口吃透 import 图，比全仓 blacklist 可控得多。协议 md 等文件依赖显式外挂 assets。web-ui server 和 classifier 体量小，Stage 1 就够了。

B 只用在一个刀刃上，原因：

1. `loadProtocolFile()` 从源码目录读提示词 md——bundler 看不见这个依赖，打包后启动即缺文件
2. `pi-coding-agent` 是 tarball 黑盒，内含不确定的动态加载，import 图追到边缘情况全靠手工排雷
3. `fastify`/`pg` 生态的 CJS 边缘情况，漏一个就是客户机器上的运行时崩溃

### 打包脚本（实施定稿）

位置：`deploy/layers/meerkat/desktop/scripts/`，不进 `build.rs`。

| 脚本 | 职责 |
|---|---|
| `scripts/stage-payload.sh` | 唯一入口：拷 Node 24 运行时 → `bundle.mjs`（esbuild 把 core 和 web-ui server 各打成单文件 mjs）→ 拷协议 md / tiktoken wasm → 构建 web-ui 前端 → classifier 装生产依赖 → 拷种子。实测 payload **148MB**（远低于 400MB 目标，Stage 2 的 import 图瘦身未启用） |
| `scripts/bundle.mjs` | esbuild 打包 core / web-ui server（被 stage-payload.sh 调用，也可单独跑） |
| `scripts/stage-payload.ps1` | 同上，Windows PowerShell 版 |
| `scripts/verify-payload.sh` | 冒烟验证：从 payload 启动 core 跑一轮对话 + 分类路由 |
| `scripts/cargo-msvc.bat` | Windows 下给 cargo 补 MSVC 环境 |

脚本不进 `build.rs` 的理由：

- **反馈环**：staging 是分钟级重活，`build.rs` 每次 `cargo build` 都跑——开发迭代会被拖死。staging 必须是显式执行、可缓存的独立步骤
- **可测性**：打包脚本能脱离 cargo 单独跑、单独验证（CI 里 per-OS matrix 各跑各的）
- **fork 规则**：组织专属内容集中在 `deploy/layers/meerkat/desktop/`，边界干净

`build.rs` 的职责（实施定稿）：payload 目录不存在的哑检查 + **声明 app 命令清单**（`AppManifest::commands`，tauri-build 据此为 6 个命令生成 `allow-*` ACL 权限，见第八节 WebView ACL）。release 构建通过 `tauri.conf` 的 `beforeBuildCommand` 挂 staging 脚本，dev 构建跳过。

### 工程目录布局

```text

  seeds/                  ← 种子配置（打包进 payload/config/）

    providers.local-secure.json
```

## 第七节：自动更新

### 全量更新（tauri-plugin-updater）

v0.1 做全量更新。Tauri 壳 + Node 载荷整体发版，检测到新版本后下载完整安装包，用户点一下重启升级。

分离更新（壳和载荷分开发版）v0.1 不做。分离更新的收益前提——壳稳定、载荷频繁更新——在首版不成立。首版壳和载荷都在快速修 bug，更新频率是耦合的，省不了几次"只更载荷"的下载，却背上两套更新逻辑 + 兼容矩阵的永久成本。

分离更新的启动条件（写进文档防止以后拍脑袋）：当三个信号同时出现再升级——①壳连续 2-3 个版本零变更 ②载荷进入周更节奏 ③客户开始抱怨更新体积。届时契约已被时间证明稳定，加第二通道的风险可控。

### 落地要点

- **更新源**：任意 HTTPS 静态托管（OSS/自己的服务器）放 `latest.json` + 安装包。私有 GitHub Releases 客户拿不到，不踩这个坑。**现状：tauri.conf.json 的 endpoints 仍是占位符（`updates.example.com`），接入真实托管地址后自动更新才真正生效（遗留项）**
- **签名**：tauri signer 私钥进 CI secrets。发布流程 = CI 产物 → 签名 → 更新 manifest
- **一个包发所有客户**：令牌是装后录入的，安装包无客户差异——托管和分发都简单
- **更新不丢数据**：SQLite、令牌、connector secret 全在 DATA_DIR（用户目录），覆盖安装分毫不受影响
- **离线客户**：自动更新天然够不着，手动覆盖安装通道必须保留。A 是给在线客户的增量便利，不是替代手动通道

## 第八节：安全

### 网络边界

- core 只绑 `127.0.0.1`，不接受外部连接
- classifier 只绑 `127.0.0.1`
- web-ui 只绑 `127.0.0.1`

### 进程间认证

- 首启随机生成 `CORE_SIGNING_SECRET`（32 字节），存 DATA_DIR
- web-ui ↔ core 全链签名（chassis `signedHeaders` + `withSourceAuthNonce`，机制现成）
- 无 token 的请求 → core 直接拒

### 桌面登录链路

设置 `CORE_SIGNING_SECRET` 后，web-ui 从 dev cookie 模式切到 portal 模式（`COOKIE_AUTH = !CORE_SIGNING_SECRET`，`plugins/web-ui/server/index.ts:36`），需要 `PORTAL_IDENTITY_SECRET` 签发的身份令牌才能登录。

桌面版登录链路（实施定稿，与设计初稿的差异加粗标注）：

1. 首启同时生成 `PORTAL_IDENTITY_SECRET`（32 字节），**与其他 secret 一起存于 `DATA_DIR/secrets.json`（单文件，ACL 限当前用户）**——初稿的三个独立 `.bin` 文件在实施中合并为 secrets.json
2. **Tauri 壳提供 `portal_token` command：前端 splash 页（本地来源）调用后由 Rust 用 `PORTAL_IDENTITY_SECRET` 签发 token**（payload 含固定 principal `meerkat-desktop`，**TTL 24 小时**——初稿的"无过期"在实施中收紧为 24h），**token 以 query 参数带给 web-ui 页面，页面存入 localStorage 后续命**（初稿的"注入 WebView 初始请求 header"经 spike 验证对后续 XHR 不续命，改为 query + localStorage 方案）
3. web-ui 的 `authenticate()` 在 portal 模式下验签 → 通过 → 以 `meerkat-desktop` 用户身份进入主界面
4. 无需用户登录——桌面是单用户应用，身份 = 本机

**WebView ACL（实施中新增）**：web-ui 页面对 Tauri 而言是远程来源（http://127.0.0.1），默认无权调用任何 Rust 命令。`capabilities/` 下两份清单收口：本地 splash 来源保留全部 6 个命令；web-ui 来源只放行 `restart_core`（设置页保存代理后重启 core 用）——`portal_token`（能铸管理员令牌）保持本地专属。

```text
Tauri 壳                                web-ui                  core
  │                                       │                      │
  │─ 签发 portal-identity token ─▶        │                      │
  │  (PORTAL_IDENTITY_SECRET,             │                      │
  │   p=meerkat-desktop)                  │                      │
  │                                       │─ verify → 200 /me ─▶│
  │                                       │◀─────────────── 200  │
  │◀────────── WebView 直接进主界面 ──────│                      │
```

### Token 存储

- tensoris 令牌通过 admin API 进 core 的加密存储（connector secret 加密，机制现成）
- connector secret 首启生成，文件权限 0600，重启不变化

### 无沙箱风险

客户机没有 Docker → execute/write/read 工具不可用。v0.1 不尝试工具裸跑（违背安全设计）。产品需明示：对话与路由能力完整，资料查找和报告生成待后续版本。需求二（自研沙箱）落地后以资源形式打进安装包。

## 第九节：不做

- 不做在线激活服务/授权码换领系统（令牌 = 授权码，控制台直发）
- 不做用户可编辑的 providers 配置文件（种子只读，管理走 UI）
- 不做 BYOK 完整管理页（高级折叠项，后续版本）
- 不做分离更新（条件见第七节）
- 不做构建时全量 import 图分析（B 只在 A 超标时精准用）
- 不做移动端（iOS 不允许 sidecar 子进程形态，移动端是远程后端 + 轻客户端的另一套架构，独立立项）
- 不做托盘常驻（窗口应用，用完即关；后续版本再加）

## 第十节：与 v0.0 的关系

v0.0（tag `meerkat-v0.0.0`）已完成语义路由 + 会话锁 + Skill Packs 三条能力线，并经过实施、测试、封存。v0.1 是在 v0.0 的能力基线上做桌面化封装——路由、锁、Skills 本身不需要改动，但它们的存储后端和运行环境从"服务端 Postgres"变为"桌面 SQLite"。

| 基础设施 | 状态 | v0.1 如何消费 |
|---|---|---|
| 语义路由 + 会话锁 | v0.0 已实现 | 接口不变；`sessionLockStore` 在桌面版自动走 SQLite，满足"会话和锁必须同后端"硬约束 |
| Skill Packs | v0.0 已实现 | 拉取、物化、导入逻辑不变；桌面版增加本地文件导入通道（`allowLocalRepos` production 放开） |
| `SessionStore` | v0.0 Postgres | v0.1 新增 SQLite backend，接口对齐 Postgres 版 |
| `DurableMap` | v0.0 `artifactMap` 双后端（Postgres/memory） | v0.1 新增 SQLite 第三后端，`artifactMap` 自动选择 |
| `CORE_SIGNING_SECRET` | v0.0 已有 | v0.1 首启生成，配套补全 `PORTAL_IDENTITY_SECRET` + 桌面登录链路 |

v0.1 的 core 改动以 additive 为主——新增 SQLite 双后端、补 `/health` 端点、受控的本地 skill 导入。不修改 v0.0 的语义路由、锁、Skills 核心逻辑。

**实施期新增的三处内核缝改动（超出上表，均有 ADR 背书）**：

| 改动 | 触发 | 决策 |
|---|---|---|
| `resolveModel()` 自定义供应商注册优先于内置同名型号 | 实测：tensoris 以本名代理 gpt-5.4-nano 等型号，被 pi-ai 内置注册表遮蔽导致 403 | ADR-007 |
| `SKILL_PACK_GIT_PROXY` 显式代理开关 | 实测：国内直连 GitHub 间歇被断，skill pack 拉取看运气 | ADR-008 |
| 会话锁管理面（list / retarget / release + 桌面锁管理页） | 实测：本地模型不可用时锁死会话永久不可用 | ADR-009 |

另有两处小修：空文本唤醒 turn 跳过分类（`8b11b42`）、`CLASSIFIER_TIMEOUT_MS` 可配置默认 15s（`4b84396`）。
