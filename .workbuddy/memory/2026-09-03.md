## 排查 dev 实例"服务断开"
- 现象：用户报告服务可能断开。检查发现 `dev status` 显示 `0 taken / 0 free / 0 slots`（实例没了），端口返回 502（不是连接失败），Postgres 容器 `qm-dev-postgres` 仍 `Up 16 hours`。
- **根因：qm 自带的空闲自动回收**。`scripts/dev/supervisor/main.ts:33-39` 定义 `IDLE_HOURS`，默认 **8 小时**；第 555-566 行 idle 检查超时后执行 `idle self-teardown`，并删除 lease 目录。昨天 18:40 最后一次操作，今天 08:50（约 14h）触发回收，`pool1.lock` 被删。
- **不是故障，是设计行为**。数据全未丢失（Postgres 容器仍活）：admin grants、DeepSeek provider（含加密 key）、runtime 配置全部完好。
- 修复：重启时加 **`DEV_INSTANCE_IDLE_HOURS=0`** 禁用自动回收（源码里 `n < 0` 才报错，0 合法；`IDLE_HOURS > 0` 才启用检查）。
- 重启后验证：portal/admin 200、core 401（预期，需 portal 签名）、provider `hasKey:true` 两模型在、runtime 仍为 `pi + deepseek-v4-flash`。

## 修复：web-ui 发消息报 HTTP 403 "that model is not enabled for the web UI"
- **根因**：web turn 若显式带 `model` 参数，QM 用 `DEFAULT_WEBUI_MODEL_IDS`（内置 web 白名单）校验（`src/core/turn-options.ts` `validateWebTurnModelOptions`），自定义模型 deepseek 不在其中 → refused → 403。不带 model（走 org runtime 默认 deepseek-v4-flash）则能通。
- **修复**：通过 admin API 设 org 的 webui-models 白名单。`PUT /v1/admin/scopes/org:acme/webui-models` body `{ids:["deepseek-v4-flash","deepseek-v4-pro"]}`（admin-resources.ts:477 `webui-models` 资源，target org，clearable，空列表恢复默认）。
- **验证**：带显式 model 的 turn 从 403 → 202 queued → DeepSeek 真实回复 "Hi! 👋 ..."。不带 model 的一直通。
- 关键：org runtime 默认已是 deepseek-v4-flash，`baseModelOptions` 含 deepseek 两模型，`webuiModelConfig` 原本 n/a。修复后需保证 deepseek 在 web 白名单才能被显式选择。
- 测试方法：写脚本 import `signedRequestHeaders`+`completeDevSecuritySecrets`（seed=databaseUrl）对 core 8081 发 `POST /v1/turns`，构造 `{surface:"web", actor:{externalId:zamir}, conversation:{kind:"dm",threadRef:"web:zamir:xxx"}, text, liveActor:true, model, harness:"pi"}`。显式带 model 复现 403，去 model 走默认则通。
