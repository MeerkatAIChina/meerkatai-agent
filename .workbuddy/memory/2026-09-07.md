## QM 与模型联调：服务器现状调研（超长上下文）
- 目标：让本地 QM 用服务器上的 Meerkat-TRIZ-v1 模型，实现「一次性输出 10 万字文档」。
- 通过 paramiko SSH（系统 Python 3.11 装了 paramiko 5.0.0）连上 `meerkat@192.168.60.102` 摸清现状（只读调查，未改任何东西）。
- **服务器**：`spark-f5a5`，Ubuntu 24.04 aarch64，NVIDIA GB10（DGX Spark），121G 统一内存（已用 110G，vLLM 占 97.5G）。
- **模型结构（关键）**：Meerkat-TRIZ-v1 不是独立模型，而是挂在 Qwen3.6-35B-A3B（NVFP4 量化，MoE 35B/激活3B）上的 LoRA 适配器（r=64，169MB，路径 /models/adapter）。
- **当前 vLLM 参数**：`--max-model-len 262144`（256K 已开）、`--gpu-memory-utilization 0.83`、`--max-num-seqs 64`、`--override-generation-config {"max_new_tokens":16384}`（单次输出仅 16K）。
- **结论**：上下文不是瓶颈（base 原生 262K，YaRN 可到 1M）；真正卡点是 `max_new_tokens=16384`（≈1.2万字）。
- **可行性**：模型输出硬顶 = 81920 token ≈ 6 万字（官方 max output），10 万字单次输出做不到。可选方案：① 调 max_new_tokens 到 81920（到6万字）；② QM 分段生成拼接（可到10万字）；③ 换输出上限更高的 base 模型。
- 调研结果已写入 `docs/meerkat/v0.1.3/需求调研.md` 的「超长上下文的需求调研」章节（用户确认写到 v0.1.3 而非字面的 v0.1.2）。
- 已清理含明文密码的临时脚本（ssh_probe*.py、askpass.sh）。
- 服务器凭据：ssh meerkat@192.168.60.102 / 密码 meerkat123 / API key e542...c41（64位hex）。
