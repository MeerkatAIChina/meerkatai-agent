## sandbox 镜像构建完成，execute 工具解锁
- 构建时踩坑：`fly/Dockerfile` 用 `FROM node:24-slim@sha256:...` 带 digest 引用，Docker Hub `auth.docker.io` 间歇性超时（两个 IP 都失败过），导致 build 阶段 load metadata 反复失败。
- 解法：先手动 `docker pull node:24-slim@sha256:6f7b...` 和 `debian:12-slim@sha256:7b14...`（带 digest 精确拉取，重试几次直到成功），命中本地缓存后再 build，成功。
- 产出镜像：`qm-sandbox-base:dev` + `qm-sandbox-local:latest`。
- `local-sandbox-smoke.ts` 全 PASS：冷启动、exec、数据持久化（warm restart marker 保留）、scratch 沙箱，均验证通过。sandbox guest 是 `x86_64 | v24.18.0`（精确对齐 .node-version）。
- 关键结论：sandbox 镜像在 provision 时才检查（`local-sandbox.ts:119`），故构建完成后**无需重启 dev 实例**。

## 接入 DeepSeek 自定义模型（完成）
- qm 原生支持自定义 provider（`src/model/custom-providers.ts` + `custom-provider-store.ts`），协议支持 `openai`/`anthropic`，key 加密存 Postgres。
- DeepSeek 模型命名：旧别名 `deepseek-chat`/`deepseek-reasoner` 已于 2026-07-24 停用；现用 `deepseek-v4-flash`（快/便宜）、`deepseek-v4-pro`（强推理，贵约 3x）、`deepseek-v4-flash-vision-exp`（视觉实验）。baseUrl `https://api.deepseek.com`。
- 注册方式：admin API `PUT /v1/admin/custom-providers/:id`，body `{name, protocol:"openai", baseUrl, models:[{id,name,contextWindow,maxTokens}], apiKey, validate}`。鉴权 = source-auth 签名（`signedRequestHeaders`）+ `x-admin-actor: <principal>@<org>`。
- 关键坑：**dev 实例的 signing secret 是确定性生成的**——`completeDevSecuritySecrets(env, seed)` 里 `secret = sha256Hex("qm-dev\0"+seed+"\0"+KEY)`，seed = databaseUrl（`postgres://postgres:qm-dev@127.0.0.1:55432/qm_dev_<sha1(worktree)[:12]>`）。用项目自己的函数 import 即可复现签名。
- 管理员身份：supervisor 用 `$USER` seed，WSL 里是 **`zamir`**（不是 dev-admin），grant 存 `admin_grants` 表 `zamir|org:acme|org_admin`。
- 切换真实模型：`assembleEnv` 硬编码看 `ANTHROPIC_API_KEY`（不看自定义 provider），故用假 key `ANTHROPIC_API_KEY=sk-ant-dummy` 让 harness 判定为 pi，再通过 `PUT /v1/admin/scopes/org:acme/runtime` 设 `{harnessId:"pi", modelId:"deepseek-v4-flash"}`。自定义模型 `modelServiceable` 返回 true（`pi-models.ts:265`），不依赖内置 key。
- 结果：DeepSeek key + 两个模型均验证有效；runtime 已切到 pi + deepseek-v4-flash；portal/admin 200。
- 遗留：尚未发真实 turn 端到端验证（`POST /v1/turns` 需完整 TurnRequest，建议用户浏览器发消息验证）。
